02

Problem Statement

Enterprise teams using Microsoft SharePoint struggle with document chaos - files scattered across folders, no version control, compliance nightmares, and hours wasted searching for the right document. Existing solutions like Google Drive or Dropbox are not built for enterprise compliance needs, while enterprise alternatives like M-Files are expensive, complex, and require separate systems outside Microsoft 365.

Document Discovery is Broken

Employees spend an average of 2+ hours per week searching for documents. SharePoint's native search is powerful but not intuitive for everyday users.

Compliance is a Constant Risk

Without proper version control, audit trails, and permission management, every document is a potential compliance violation waiting to happen.

No Unified System

Teams use a mix of SharePoint, email attachments, and personal drives. There's no single source of truth - leading to duplicate files and outdated versions.

Existing Tools Don't Fit

Google Drive and Dropbox lack enterprise compliance. M-Files is expensive and lives outside Microsoft 365. Companies need something native and affordable.

03

Target Users

DocVault was designed for three distinct user types within an enterprise organisation. Each has different needs, different pain points, and different success metrics. Getting this right was the foundation of all design decisions.

Business Users

Day-to-day employees who need to find and use documents quickly.

  • Fast document search and discovery
  • Simple upload and organisation
  • No technical knowledge required
  • Access right documents, right away

Compliance Managers

Responsible for ensuring the organisation meets regulatory requirements.

  • Full audit trail of every document action
  • Version control with rollback capability
  • Permission management and access logs
  • Compliance reporting at a glance

IT Managers

Responsible for deploying and maintaining the system.

  • Easy deployment within Microsoft 365
  • No separate infrastructure to manage
  • Role-based access configuration
  • Integration with existing SharePoint setup

05

Key Design Challenges

Designing DocVault presented three unique challenges that shaped every decision - from the information architecture to the visual language.

Making Compliance Feel Simple

Compliance features are inherently complex - audit trails, permissions, version history. The challenge was presenting this complexity in a UI that feels clean and approachable. Solution: progressive disclosure - show the simple view first, advanced controls only when needed.

Designing for 3 Different Users

Business users, compliance managers, and IT managers all have completely different mental models and success criteria. A single UI had to serve all three. Solution: role-based dashboard views and contextual navigation that surfaces the right information for each user type.

Landing Page That Converts

The DocVault landing page needed to explain a complex enterprise product clearly enough to drive sign-ups. Enterprise buyers are skeptical. Solution: lead with the pain point, follow with social proof, end with a simple pricing model. No jargon above the fold.

User Flows Designed

I mapped out 3 primary user flows before designing any screens. These flows became the backbone of the entire application architecture.

Document Upload & Organisation Flow

User type: Business User
Login to DocVault via SharePoint → Navigate to target folder → Drag and drop files → Add metadata tags → Set permission level → AI indexes document → Version 1.0 created

Compliance Audit Flow

User type: Compliance Manager
Access Compliance Dashboard → Select document to audit → View activity timeline → Filter by user/action/date → Export audit report → Flag suspicious activity → Send to stakeholders

Document Approval Workflow

User type: Business User + Manager
Submit for approval → Manager notified → Review with comments → Approve / Reject / Request changes → User notified → Version locked → Audit trail updated

Key Design Decisions

These decisions were intentional and grounded in user behaviour and enterprise UX principles.

Microsoft Fluent Design Language

DocVault lives inside SharePoint - so it had to feel native. I followed Microsoft Fluent design tokens for color, spacing, and components while layering DocVault's brand identity on top. Users feel at home from day one.

Progressive Disclosure for Compliance

Compliance features are complex. Showing everything at once overwhelms users. I used progressive disclosure - simple view by default, with advanced controls one click away. This made the product feel approachable without sacrificing depth.

Role-Based Dashboard Views

Three different users, three different dashboards. Business users see recent documents. Compliance managers see audit alerts. IT managers see system health. Same product, personalised entry point.

12

Reflection

DocVault was my most complex design challenge to date - a real product, real stakeholders, real business goals.

✦

Designing for enterprise is designing for behaviour change

Enterprise users have deeply ingrained habits. DocVault had to feel familiar enough to adopt immediately but powerful enough to replace existing chaos. The Microsoft Fluent foundation was the right call.

✦

The landing page is a product, not a brochure

I treated the landing page as a conversion product - with a clear user journey, objection handling, and calls to action at every scroll depth. This mindset shift changed how I structured every section.

✦

Three users means three success metrics

I should have defined what success looks like for each user type before designing a single screen. Business users measure time-to-find. Compliance managers measure coverage. IT managers measure deployment time.

✦

What I'd do differently

I'd run at least 3 user interviews per user type before finalising the IA. Enterprise users have specific workflows that are hard to guess from the outside. Even informal conversations would have sharpened the design significantly.
